# Runbook — инструкции на каждый сбой и отказ

> **Читай первым делом.** Эта система намеренно **деградирует молча** и
> грузится дальше: отсутствие ошибки на экране ≠ отсутствие проблемы.
> Диагностических поверхностей ровно две:
>
> 1. **tty2** — `Ctrl+Alt+F2` (переключайся **из меню**, не из RDP-сессии;
>    в сессии VT-переключение заблокировано). Логин: `root` + пароль сборки.
>    Сюда идёт весь вывод загрузки и init-скриптов (ядро загружено с
>    `console=tty2`).
> 2. **`/var/log/xsession.log`** — лог последней RDP-сессии (X + xfreerdp).
>
> Почти каждый «тихий» симптом ниже молчит только на **tty1** (там меню) —
> корроборируй на **tty2**. Вернуться в меню: `Ctrl+Alt+F1`.

Формат записи: **Симптом** · **Тихо?** · **Где всплывает** · **Причина**
(файл:строка) · **Проверить** · **Что сделать**.

## 1. Загрузка / загрузчик

### 1.1 BIOS не видит флешку
- **Тихо?** да (ничего не грузится). **Где:** прошивка/boot-меню.
- **Причина:** режим USB в BIOS. **Проверить:** boot-меню (F11/F12/Esc).
- **Что сделать:** в BIOS включить USB-HDD, отключить «USB legacy floppy»;
  разметка образа — обычный MBR, большинство BIOS её ест.

### 1.1a «Boot error» сразу после выбора флешки (usb.img, старый BIOS)
- **Тихо?** нет (одна строка «Boot error»). **Где:** загрузочный сектор
  syslinux (первая стадия, до меню/ядра).
- **Причина:** старый BIOS без EDD читает USB в CHS-режиме, а первая стадия
  syslinux считает адреса по геометрии из BPB FAT-раздела. В образах до
  v1.2.1-41 BPB имел «16 голов/32 сектора» и hidden=0 — на железе, которое
  маппит USB как 255/63, чтение уходило мимо. В qemu/новых BIOS (EDD/LBA)
  не проявляется — образ там грузится.
- **Что сделать:** пересобрать/взять образ от v1.2.1-41+ (mkfs.vfat
  `-g 255/63 -h 2048`) и перезалить флешку целиком. Если «Boot error»
  остался — перезаписать флешку заново (сбойная запись) и проверить сам
  носитель; в BIOS выставить режим USB-HDD.

### 1.2 UEFI-машина не грузится / «no bootable device»
- **Тихо?** да. **Где:** прошивка.
- **Причина:** (а) включён **Secure Boot** — grub-efi не подписан; (б) EFI
  не собрался в образ (см. [7.4](#74-efiuefi-молча-не-собрался)).
- **Проверить:** в прошивке статус Secure Boot; на образе — есть ли
  `EFI/BOOT/bootx64.efi` (примонтируй флешку на другом компе).
- **Что сделать:** отключить Secure Boot или включить legacy/CSM. Подпись
  shim — в планах.

### 1.3 Чёрный экран сразу после загрузчика
- **Тихо?** да (пустой экран). **Где:** экран монитора.
- **Причина:** редкая прошивка без VESA-режима 1024×768; `vga=791` в
  `board/thinclient/syslinux.cfg:13`. Под UEFI `vga=` не используется —
  проблема только BIOS.
- **Проверить:** загрузка на другой машине/в QEMU.
- **Что сделать:** воткни флешку в другой комп и **убери `vga=791`** из
  строки `APPEND` в `syslinux.cfg` на загрузочном разделе. Правка cmdline на
  лету **отключена** (`NOESCAPE 1`, `syslinux.cfg:2`) — только через файл.

### 1.4 (Было раньше, теперь закрыто) `init=/bin/sh` у стойки
- Интерактивный `boot:` заблокирован `NOESCAPE 1` / `ALLOWOPTIONS 0`.
  Побочно — см. 1.3 про recovery.

## 2. Заставка / ранний init

### 2.1 Нет заставки и прогресс-бара, «висит»
- **Тихо?** да. **Где:** tty1 пустой; ищи на **tty2**.
- **Причина:** нет `/dev/fb0` — заставка пропускается
  (`etc/init.d/S00splash:6` `[ -e /dev/fb0 ] || exit 0`). Часто вместе с 1.3.
- **Проверить (tty2):** `ls -l /dev/fb0`, `dmesg | grep -i -E 'drm|fb'`.
- **Что сделать:** дать framebuffer (см. 1.3, `vga=791` для BIOS; под KMS
  проверь драйвер видео). Система при этом рабочая — меню появится на tty1.

### 2.2 Прогресс-бар застрял
- **Тихо?** да. **Где:** заставка.
- **Причина:** какой-то init-шаг завис; отметки прогресса: `S00splash`(10) →
  `S35console`(30) → `S50flash`(55) → `S51network`(80) → `S98splashdone`(100).
  Значение бара = докуда дошли (сеть теперь ПОСЛЕ флешки — читает tc.conf).
- **Проверить (tty2):** `Ctrl+Alt+F2`, смотри последние строки; `dmesg`.
- **Что сделать:** по застрявшему шагу — соответствующий раздел ниже
  (сеть → 4, флешка → 3).

### 2.3 Заставка не гаснет (поверх меню)
- **Тихо?** да. **Причина:** не отработал `S98splashdone` (`psplash-write
  QUIT`). **Проверить (tty2):** `pgrep psplash`. **Что сделать:** `psplash-
  write QUIT` или `killall psplash`; смотри, почему rcS не дошёл до S98.

### 2.4 Кракозябры вместо кириллицы
- **Тихо?** да (двойной fallback молчит, `S35console:7-8`). **Причина:**
  не загрузился шрифт `UniCyr_8x16`/`cyr-sun16`. **Что сделать:** имена
  серверов — латиницей (`servers.conf.sample:2`); проверь наличие
  `setfont` и шрифтов пакета kbd.

## 3. Хранилище / конфиг

Диагностическая база (tty2): `mount | grep flash`, `ls -l /mnt/flash`,
`ls /dev/sd*`, `dmesg | grep -i sd`.

### 3.1 «No servers configured» в меню
- **Тихо?** полу-тихо (это и есть сообщение, но причина скрыта). **Где:**
  tty1 меню (`tc-launcher.c:161`).
- **Причина, НЕОТЛИЧИМЫЕ на вид:** (а) `servers.conf` не найден/флешка не
  смонтирована; (б) файл есть, но все строки битые (нет `;`, начинаются с
  `#`, пустое имя/ip — молча пропускаются, `tc-launcher.c:64-68`); (в)
  носитель не найден вовсе (см. 3.4).
- **Проверить (tty2):** `cat /mnt/flash/servers.conf` — есть ли файл и
  валидные строки `имя;ip`.
- **Что сделать:** поправить/создать `servers.conf` (формат `имя;ip`), из
  консоли — `tc-edit`.

### 3.2 «Cannot save: read-only media (ISO image)»
- **Тихо?** нет, но сообщение висит 2 сек и пропадает (`tc-menu` save_server,
  ветка `:28-30`). **Где:** tty1.
- **Причина:** запись в `servers.conf` не удалась после `remount,rw` —
  носитель read-only: CD в виртуалке, **или** раздел TCDATA не создался при
  загрузке (см. 3.4).
- **Проверить (tty2):** `mount | grep flash` (ro?), `touch /mnt/flash/x` .
- **Что сделать:** использовать `usb.img` или флешку с рабочим TCDATA; для
  CD-в-VM правка списка — только пересборкой (`servers.conf.sample`).

### 3.3 Добавленный сервер «пропал» / не сохранился
- **Тихо?** да (пустой ввод/битое поле молча отбрасываются,
  `tc-menu` `:16`/`:122`, `tc-launcher.c:232`). **Где:** tty1.
- **Причина:** пустое имя/IP, либо запись ушла на read-only носитель (3.2),
  либо запись за пределами `MAXSRV=64` (лишние молча не грузятся).
- **Проверить (tty2):** `cat /mnt/flash/servers.conf`.
- **Что сделать:** заполнить оба поля; для CD — см. 3.2.

### 3.4 Носитель с `servers.conf` не найден
- **Тихо?** на tty1 — да; на **tty2** есть строка `S50flash: носитель с
  servers.conf не найден` (`etc/init.d/S50flash:90`), boot продолжается.
- **Причина:** после 10×1с флешка/раздел не примонтировались.
- **Проверить (tty2):** `ls /dev/sd*`, `dmesg | grep -i -E 'usb|sd'`,
  `mount`.
- **Что сделать:** проверь, что образ реально записан и раздел с
  `servers.conf` есть; на медленном USB иногда помогает порт USB-2.

### 3.5 TCDATA не создался (первая загрузка с ISO-флешки) — 8 молчаливых причин
- **Тихо?** **полностью** (нет ни одного сообщения; система молча монтирует
  ISO read-only и едет дальше, `S50flash:101-104`). Отсюда потом 3.1 и 3.2.
- **Причина:** любой `return 1` в `make_data_part` (`etc/init.d/S50flash`):

  | # | Причина | Строка | Проверить на tty2 |
  |---|---|---|---|
  | 1 | носитель — CD (`*/sr*`) | `:43` | `ls /dev/sr*` |
  | 2 | не блочное устройство | `:45` | `ls -l /dev/sd*` |
  | 3 | нет `sfdisk` | `:49` | `command -v sfdisk` |
  | 4 | нет `mkfs.vfat` | `:50` | `command -v mkfs.vfat` |
  | 5 | `sfdisk --append` упал | `:52` | `sfdisk -l /dev/sdX` |
  | 6 | раздел не появился (5с) | `:59` | `ls /dev/sdX2; blockdev --rereadpt /dev/sdX` |
  | 7 | `mkfs.vfat` упал | `:60` | `mkfs.vfat -n TCDATA /dev/sdX2` вручную |
  | 8 | `mount -t vfat` упал | `:64` | `mount -t vfat /dev/sdX2 /mnt` |
  | (9) | не скопировался seed | `:66` | `cp /tmp/servers.seed /mnt/...` |

- **Что сделать:** воспроизвести шаг вручную на tty2 по таблице; на здоровом
  железе успешная первая загрузка печатает на tty2 `S50flash: конфиг-раздел
  TCDATA готов` (`:99`).

### 3.6 На dd'нутом ISO «TCDATA» = EFI-раздел
- **Тихо?** да. **Причина:** если раздел 2 уже существует и FAT
  (`S50flash:48/64`), система его подхватывает и пишет туда `servers.conf` —
  на isohybrid-флешке это ~6 МБ EFI-раздел. **Что сделать:** не критично
  (добавляется один файл); для чистого TCDATA — перезалить и дать системе
  создать раздел самой.

### 3.7 tc-edit сказал «saved», но правок нет / флешка осталась rw
- **Тихо?** обманчиво (ложный success). **Где:** tty1/консоль
  (`usr/bin/tc-edit:19-20` печатает безусловно).
- **Причина:** статус `remount,ro` не проверяется, код редактора тоже — если
  редактор прерван или ремонт-ro не прошёл (ФС занята), сообщение всё равно
  «read-only again».
- **Проверить:** `mount | grep flash` — реально ли `ro`.
- **Что сделать:** если `rw` — `sync; mount -o remount,ro /mnt/flash` руками
  до выдёргивания флешки. Не выдёргивать флешку, пока не подтвердил `ro`.

### 3.8 Запаролить консоль (опционально)
- Пункт Console по умолчанию **без пароля**. Чтобы закрыть паролем — положи
  на флешку `shell.pass` с sha256-хэшем:
  `printf '%s' 'пароль' | sha256sum | cut -c1-64 > shell.pass`. Забыл пароль
  — удали `shell.pass` с флешки. Для отладки без флешки — tty2 (пароль root).

## 4. Сеть

### 4.1 `thinclient  no ip` в углу
- **Тихо?** полу (виден `no ip`, причина скрыта). **Где:** tty1
  (`tc-launcher.c:81/100`), hostname `thinclient` = tc-netup не нашёл MAC
  (`tc-netup:12-20`).
- **Причина:** нет сетевого интерфейса вовсе (нет карты/драйвера).
- **Проверить (tty2):** `ls /sys/class/net` (только `lo`?), `ip a`,
  `dmesg | grep -i eth`.
- **Что сделать:** в VM выбрать e1000/rtl8139; на железе — воткнуть
  USB-ethernet свисток (r8152/asix/cdc — поддержаны).

### 4.2 `tc-<mac>  no ip` (имя есть, IP нет)
- **Тихо?** да (udhcpc фоновый, вывод в /dev/null, `tc-netup:25-26`).
- **Причина:** интерфейс есть, но DHCP не ответил (`-t 5`, потом ретраи
  каждые 10с). Кабель/линк/нет DHCP-сервера.
- **Проверить (tty2):** `ip link` (линк up?), `udhcpc -i eth0 -n -q`
  (разовый запрос с выводом диалога).
- **Что сделать:** проверить кабель/порт/DHCP; статик-IP — в планах
  (tc.conf). IP появляется в углу сам ~через секунду после выдачи (меню
  перечитывает, `tc-menu:107`).

### 4.3 IP есть, но RDP/DNS не работает
- **Тихо?** да. **Причина:** DHCP выдал плохой DNS/маршрут (в т.ч. rogue
  DHCP — система доверяет ответам). **Проверить (tty2):**
  `cat /etc/resolv.conf`, `ip route`, `ping <шлюз>`, `nslookup <сервер>`.
- **Что сделать:** в доверенной сети — поправить DHCP; недоверенная сеть —
  известный риск (см. README «Тонкости»), hardening в планах.

## 5. Сессия / RDP

Лог: `/var/log/xsession.log` (перезаписывается каждый коннект, `tc-menu:78`).

### 5.1 Экран «Connection to … failed (…)»
- **Тихо?** нет (полноэкранный экран ошибки, `tc-menu` connect_error, ждёт
  Enter). Показывает причину + последние строки лога с ошибками.
- **Причина (варианты в скобках):**
  - `server unreachable — no route or RDP port closed` — до RDP-порта (3389)
    нет коннекта: неверный IP, сервер выключен/файрвол, либо клиент в другой
    сети (частый случай — **UTM/QEMU с NAT 10.0.2.x не видит LAN-адреса**
    вроде 192.168.0.x). Проверка идёт ДО запуска X (bash /dev/tcp, таймаут
    4с), поэтому ошибка появляется быстро, без чёрного экрана;
  - `X server failed to start` — не поднялся X (см. 5.2);
  - `xfreerdp exited with code N` — клиент вышел с ошибкой (см. 5.3).
- **Что сделать:** проверить адрес и доступность: из консоли (Settings →
  Console) `ping <ip>` и что клиент вообще в той же сети (`ip -br addr`). В
  UTM для доступа к реальному серверу нужен bridged-режим сети, а не NAT.
  Полный лог на tty2: `less /var/log/xsession.log`.

### 5.2 «X server failed to start»
- **Тихо?** нет (экран 5.1). **Причина:** X не поднялся — «no screens found»
  (не привязался KMS-драйвер, нет `/dev/dri/card0`), сбой xinit/xauth, или
  glamor-зависон на редких картах. X ведём через `modesetting` (KMS) с
  `AccelMethod none` — файл `10-video.conf`.
- **Проверить (tty2):** `cat /var/log/xsession.log`; `ls /dev/dri /dev/fb*`;
  `dmesg | grep -iE 'i915|drm'` — привязался ли видеодрайвер к чипу.
- **Что сделать:** если есть `/dev/dri/card0`, X должен подниматься сам; если
  KMS не привязался (нет `card0`) — совсем древний чип без KMS: заменить в
  `10-video.conf` `Driver "modesetting"` на `"fbdev"` и убедиться, что
  `vga=791` даёт `/dev/fb0` (1.3/2.1).

### 5.3 «xfreerdp exited with code N» / не подключается
- **Тихо?** нет (экран 5.1). **Причина:** неверный адрес, хост недоступен,
  порт 3389 закрыт, отказ NLA/учёток, **кривые часы** (NLA/Kerberos падают
  при расхождении времени — задай `NTP_SERVER` в tc.conf), несовместимость
  TLS (голый 2008 без R2 хочет TLS 1.0 — включи TLS 1.2 на сервере,
  KB4019276).
- **Проверить (tty2):** `date` (время верное?), `ping <сервер>`,
  `tcpdump -i eth0 port 3389`, строки в `/var/log/xsession.log`.
- **Отладка с консоли:** `tc-rdp -n <ip>` — показать собираемую команду и
  TCP-проверку порта, не подключаясь; `tc-rdp -v <ip>` — подключиться с
  подробным логом FreeRDP (потом хвост в `/tmp/tc-rdp.log`). Можно добавлять
  любые флаги xfreerdp: `tc-rdp <ip> /sec:tls /u:user`.
- **Что сделать:** по причине из лога — адрес/сеть/учётка/TLS; протокол
  сервера правится в Manage servers (3-е поле, напр. `rdp` для серверов без
  NLA/TLS).

### 5.4 Чёрный экран при подключении, меню не вернулось
- **Тихо?** да. **Причина:** X умер грязно и оставил VT в графике; страховка
  `chvt 1` (`tc-menu:80`) должна вернуть консоль. **Что сделать:**
  `Ctrl+Alt+F1` (в меню), затем tty2 для лога; при повторе — 5.2.

### 5.5 Сессия открывается, но падает при первом вводе (мышь/клавиатура)
- **Тихо?** нет (вернётся в меню / экран ошибки). **Причина:** легаси-сервер
  (Windows 2003/2008 по обычному RDP security) шлёт кэш-глифы и старые
  draw-orders; FreeRDP 2.x по умолчанию с выключенным glyph-cache и строгой
  проверкой orders — пока экран статичен, всё живёт, но первый ввод вызывает
  отрисовку → сервер шлёт эти orders → сессия рвётся.
- **Уже лечится** для серверов с протоколом `rdp`: tc-session добавляет
  `/relax-order-checks +glyph-cache` (Manage servers → Security → rdp).
- **Если всё равно рвётся:** лог упавшей сессии сохраняется на флешку —
  `lastsession.log` (вынь флешку, прочти на любом компе). Пробуй вручную:
  `tc-rdp -v <ip> /relax-order-checks +glyph-cache` (или без `+glyph-cache`,
  либо `/gdi:sw`, либо `-clipboard`). Часто помогает поднять цветность
  `RDP_EXTRA=/bpp:32` или, наоборот, снять `/dynamic-resolution`.

## 6. Удалённый доступ / SSH

### 6.1 «REMOTE HOST IDENTIFICATION HAS CHANGED»
- **Тихо?** нет (предупреждение ssh-клиента). **Причина:** host-ключ
  меняется между загрузками. На **usb.img** ключ персистится на флешке
  (`/mnt/flash/dropbear/`) и не меняется. На **read-only носителе** (ISO/CD,
  напр. в UTM) писать некуда → ключ эфемерный, в RAM (`/run/dropbear`), и на
  каждую загрузку новый.
- **Что сделать:** для стабильного ключа — грузиться с `usb.img` или с
  флешки, где создался раздел TCDATA. На ISO/CD это норма: убрать строку из
  `~/.ssh/known_hosts` или `ssh -o StrictHostKeyChecking=no`.

### 6.1a «Connection closed by <ip> port 22» (сразу, до пароля)
- **Тихо?** нет (ошибка ssh-клиента). **Причина:** порт открыт (dropbear
  слушает), но соединение рвётся на рукопожатии — обычно host-ключ: не создан
  каталог для ключа, либо ключ битый (обрыв питания при первой генерации).
  Историческая дыра: bare `dropbear -R` писал в `/etc/dropbear ->
  /var/run/dropbear`, которого при загрузке нет. Исправлено в S53ssh (явный
  `-r`, RAM-каталог `/run/dropbear`, проверка/перегенерация ключа).
- **Проверить (tty2/Console):** `ls -l /mnt/flash/dropbear /run/dropbear`
  (ключи есть и не нулевые?); в форграунде `killall dropbear; /usr/sbin/dropbear
  -F -E -r <rsa> -r <ecdsa>` и смотреть ошибку при коннекте.
- **Что сделать:** обновить образ (фикс в S53ssh); битый ключ на флешке
  вылечится сам (валидация в gen_key), либо вручную `rm -f
  /mnt/flash/dropbear/*` и `/etc/init.d/S53ssh restart`.

### 6.2 ssh: Permission denied
- **Тихо?** нет. **Причина:** неверный пароль root (задаётся при сборке
  `TC_ROOT_PASSWORD`, не публичный) — либо, если включён `-s -g` overlay,
  парольный вход выключен и нужен ключ.
- **Что сделать:** использовать пароль сборки; при key-only — положить
  публичный ключ (провижен с флешки — в планах).

### 6.3 На tty2 при загрузке `Starting dropbear sshd: FAIL`
- **Тихо?** нет (на tty2). **Причина:** демон не стартовал → SSH нет.
- **Проверить (tty2):** `dropbear -F` вручную, смотреть ошибку.

## 7. Сборка / заливка

### 7.1 «usb.img пропущен: нет утилиты syslinux»
- **Где:** stderr сборки (`post-image.sh:145`). **Причина:** нет `syslinux`.
- **Что сделать:** на Apple Silicon это норма (usb.img дособирается
  amd64-шагом `build.sh`); на Linux — поставить `syslinux`.

### 7.2 «ISO пропущен: нужны xorriso и isolinux»
- **Где:** stderr (`post-image.sh:108`), сборка «успешна» без ISO.
- **Что сделать:** поставить `xorriso` и `isolinux`.

### 7.3 «mbr.bin не найден — установи syslinux-common» (fatal)
- **Где:** `post-image.sh:83`, сборка падает. **Что сделать:** поставить
  `syslinux-common`.

### 7.4 EFI/UEFI молча не собрался
- **Тихо?** да (`post-image.sh` gen_efi, `2>/dev/null`, `return 1`).
  Образы собираются, но не грузятся по UEFI. **Симптом на машине:** 1.2.
- **Проверить:** есть ли `EFI/BOOT/bootx64.efi` на образе; в сборке —
  `command -v grub-mkstandalone`, `ls /usr/lib/grub/x86_64-efi`.
- **Что сделать:** поставить `grub-efi-amd64-bin`/`grub-efi-ia32-bin`
  (в Dockerfile уже есть — пересобрать образ окружения).

### 7.5 Сборка падает: root / нет утилиты
- `Не собирай Buildroot под root` (`build.sh:39`) → запусти от обычного
  пользователя. `Не хватает '<tool>'` (`build.sh:45`) → доставить пакет
  (раздел README «Сборка из исходников»).

### 7.6 Пароль root: предупреждение при сборке
- **Где:** stderr (`build.sh`, ветка без `TC_ROOT_PASSWORD`). **Причина:**
  не задан `TC_ROOT_PASSWORD` → в образ уйдёт небезопасная заглушка.
- **Что сделать:** `TC_ROOT_PASSWORD='...' ./build.sh` для боевого образа.

### 7.7 flash-usb.sh
- `Использование: … <устройство>` / `Нет img — сначала ./build.sh`
  (`flash-usb.sh`) — передать устройство / собрать образ. Подтверждение
  `!!! ВСЕ ДАННЫЕ … БУДУТ УНИЧТОЖЕНЫ !!!` — набрать `yes`. Перепрошивка
  Этчером/dd **стирает TCDATA** — список серверов вернётся к
  `servers.conf.sample`.
